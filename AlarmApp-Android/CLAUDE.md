- 목록·메인 한 줄·OS 예약이 **같은 계산 결과**를 씁니다(표시와 예약을 따로 계산하지 않음).
- 새 문구는 ko/en 같이 추가하고 키 일치 테스트로 확인합니다. 울리는 중인 알람은 재계산으로 취소하지 않습니다.

**① 퀵알람(11.7)** — 분 프리셋 1·5·10·15·30·60, 동시에 최대 5개(일반 알람 10개와 별개). 미션 없음, 알림의 중지로 바로 끄는 것이 "미션 완료 전까지 끌 수 없다"의 명시적 예외입니다. 소리는 `USAGE_ALARM`이라 무음 모드 문제(iOS에서 로컬 알림으로 만들었다가 진동이 안 나 되돌린 문제)는 Android에서는 해당 없습니다. 울린 뒤 종료하거나 사용자가 취소하면 목록에서 삭제, 예약 실패 시 행을 남기지 않습니다. 실행 화면(미션)은 열지 않습니다. 이름은 "퀵알람 N분"처럼 자동으로 붙입니다(ko/en). 메인 목록 위에 대기 중인 퀵알람(울릴 시각·남은 시간, 밀기/길게 눌러 취소)과 하단 `퀵알람`·`알람 추가` 버튼. iOS 참고: `AlarmService.createQuickAlarm/cancelQuickAlarm/purgeFiredQuickAlarms`, `Domain/Value/QuickAlarmPreset`.

**② 알람 미루기(11.6)** — 알람별 `snoozeEnabled/snoozeMinutes/snoozeLimit`(기본 끔·5분·3회, 한도 0=무제한; 간격 1·3·5·10·15·20·25·30·45·60분, 횟수 무제한·1·2·3·5·10). 켠 알람의 실행 화면에 `미루기 N분 (남은 M회)` 버튼. 누르면 **일회성 재울림 예약이 성공한 뒤에만** 지금 울림을 멈추고 화면을 닫습니다(실패하면 소리를 멈추지 않고 에러 문구). 재울림 id는 원래 알람 id와 분리해 기록하고(iOS `Domain/Model/SnoozeRecord` ↔ Room 엔티티) 원래 알람·몇 번째 미룸인지·메모를 읽었는지를 함께 저장합니다. 재울림도 실행 화면·미션을 열고 끄는 경로는 미션 완료뿐입니다. 미션 완료·알람 끄기·삭제·이번만 변경 건너뛰기·미루기 끄기 때 대기 중인 재울림을 취소하고, 앱 종료·재부팅 후에도 울려야 합니다(재부팅 때 재등록). 미리보기에서는 버튼만 보이고 누르면 예약 없이 닫습니다. 편집 화면에는 `미루기  사용 · 5분 · 3회 ›` 요약 한 줄만 두고 누르면 별도 페이지(시안 15·16번). 알림·버튼 문구 ko/en.

**③ 이번만 변경(11.3)** — 지금부터 **7일 안** 회차만(같은 요일은 한 번, 지난 회차 불가). 동작: 시각 변경/건너뛰기/메모 변경/변경 취소. 예외는 `(알람, 날짜)`로 식별하고 메모는 `기본/이번만 다른/읽지 않기`를 명시 구분합니다. 순수 로직 `Domain/Value/`의 `DayKey`·`DayExceptionValue`(+`EffectiveMemo`)·`OccurrenceResolver`는 Kotlin으로 그대로 옮길 수 있고 iOS 테스트(`AlarmAppTests/`)도 참고합니다. **예약 방식은 Android가 다를 수 있습니다(확인 필요):** iOS는 주간 반복 알람이 한 회차만 바꾸지 못해 변경 요일만 반복에서 빼고 일회성+4주치 브리지로 대체했지만(`SchedulePlan`·`OccurrenceRecord`), Android는 이미 "다음 울림 한 번만 예약하고 울리면 다음을 재예약"하는 구조(`AndroidAlarmScheduler`)라서 다음 울림 계산에 예외를 반영하는 것만으로 충분할 가능성이 큽니다. 불필요한 브리지는 만들지 말고 구현 시 확정합니다. 편집 흐름: 이번 주 일정 별도 페이지에서 한 변경은 **편집 초안에 쌓아 두었다가** 알람 편집의 `저장` 때 알람 내용과 **한꺼번에** 검증·저장합니다(새 시각이 이미 지났거나 메모가 너무 길면 아무것도 저장하지 않고 안내, 알람에서 뺀 요일의 변경은 조용히 버림, 저장 없이 나가면 함께 버림). 알람을 끄거나 삭제하면 예외도 정리하고, 요일을 바꿔 그 요일이 빠지면 그 요일의 예외를 지우며, 시각만 바꾸면 이미 걸린 예외는 유지합니다. 건너뛴 날은 소리와 메모 모두 실행하지 않습니다. 메인 위 `NextWakeLine`("8시간 24분 후에 울려요")은 켜진 알람의 앞으로 7일 중 가장 빠른 실제 울림(예외 반영, 퀵알람·미루기 재울림 제외)까지 남은 시간을 작은 텍스트로만 보여 줍니다.

**④ 메모 읽어주기(11.5)** — 알람별 `메모 읽어주기` 토글이 기능 스위치이고 **켰을 때만** 메모 입력(최대 200자)·`들어보기`를 씁니다. 실행 화면 진입 후 **회차당 한 번** `TextToSpeech`로 읽고, 미션 시작·미션 완료·화면 종료·미루기 때 중지합니다. 미루기 재울림은 같은 회차로 보고 다시 읽지 않습니다(`memoRead`를 이어받음). 음성은 **시스템 설정(TTS 출력)을 따르고**, 앱 언어가 시스템 언어와 다를 때만 앱 언어 locale을 지정하며 메모를 번역하지 않습니다(편집 화면에 안내 한 줄). **미리보기에서도 한 번 읽습니다**(편집 화면에서 미리 듣기용). 음성 실패가 미션·알람 정지를 막으면 안 되고 메모 텍스트는 화면에도 보여 줍니다. iOS에서 겪은 문제를 미리 피하세요: ① **알람 소리와 음성이 겹쳐 안 들림** → 읽는 동안 알람 소리 볼륨을 0.1로 낮추고 끝나면 1.0으로 복구(Android는 앱이 소리를 직접 재생하므로 플레이어 볼륨/오디오 포커스로 제어 가능), ② **가끔 안 읽힘** → TTS 초기화 완료 전 호출·오디오 포커스 실패 시 "읽음"으로 기록하지 말고 시작이 확인된 뒤에만 기록하며 재시도, 알람 소리 정지/정리가 읽는 중인 음성을 끊지 않게(iOS는 알람 소리 정지가 오디오 세션을 꺼서 음성이 끊겼음), 앱이 막 열린 직후 비활성 상태에서의 시작 실패 대비. 음성 볼륨·정책은 실기기에서 보정합니다. iOS 참고: `Adapter/Device/MemoSpeaker.swift`(음성), `Adapter/Device/RingSoundPlayer.swift`(`duckedVolume = 0.1`), `UI/Ring/RingView.swift`(읽기 시작·중지 시점).

**⑤ UI 개편(iOS 반영분)** — 알람 편집은 시트가 아니라 **푸시 화면**(메인에서 새 페이지로 이동, 상단 뒤로가기·삭제 휴지통, 저장은 하단)이고 저장 전 변경이 있으면 뒤로 갈 때 "변경한 내용을 버릴까요?"(`버리기`/`계속 편집`). 이번 주 일정과 미루기 설정은 편집 화면의 한 줄(`이번 주 일정 ›`, `미루기 사용 · 5분 · 3회 ›`)로 이동하는 **별도 페이지**. `👑 유료 예정` 마크는 **메모 읽어주기와 이번 주 일정에만** 붙입니다(미루기는 아님, 결제·사용 제한 없음). 권한은 iOS의 "알람 권한 한 줄"이 Android에서는 알림·정확한 알람·전체 화면 알림 여러 줄이므로, 설정의 권한 화면에 줄별 상태 배지(허용됨/꺼짐/아직 묻지 않음)와 `허용하기`/`설정 열기`를 두는 구조를 참고하되 현재 Android의 권한 안내 구현을 유지·확장합니다. 권한이 없어 저장·켜기·퀵알람 만들기가 막히면 전체 화면 안내(`설정 바로 가기`/`나중에`)를 보여 주고 `나중에`여도 알람 데이터는 저장된 상태입니다.

**iOS 전용이라 Android에는 해당 없는 것**
- AlarmKit 알림 구성(중지 버튼 하나뿐인 "밀어서 중단" + `stopIntent`로 앱 열기, "미션하러 가기" 보조 버튼 제거), 카탈로그 소리 30초 제한, 무음 모드에서 앱 소리 재생을 위한 오디오 세션 처리, 앱이 열린 뒤 시스템 소리가 끊기는 문제(`keepSoundAlive`). Android는 `RingingService`가 항상 직접 재생하고 전체 화면 인텐트로 실행 화면을 엽니다.
- 기획서·시안의 "시스템 알림의 보조 버튼은 미션하러 가기" 설명은 Android에서는 전체 화면 알림→실행 화면으로 읽습니다.

## 도메인 규칙 (기획서 요약)

- 강제 기상 유틸리티: **미션을 완료하기 전에는 앱 안에서 알람을 끌 수 없습니다.**
- 알람은 최대 10개(초과 시 추가 차단). 요일 1개 이상, 타이틀 필수. 일반 알람은 반복 알람입니다. 단발은 **퀵알람(11.7)·미루기 재울림(11.6)·이번만 변경 회차(11.3)**로만 허용하며 일반 알람 10개 한도에 포함하지 않습니다(퀵알람은 별도로 최대 5개).
- 알람 필드: 시각, 요일, 타이틀, 켜짐, 미션(shake | transcription), 미디어 id, 소리 id, 따라쓰기 문장 id 목록(**빈 배열 = 전체**).
- 새 알람 기본값: 미션 = 흔들기, 미디어·소리 = 카탈로그에서 `default: true`인 항목, 시각 07:00, 요일 월~금, 타이틀 빈칸.
- 미션은 알람당 정확히 1개. **흔들기 10회**(`defaultCount`), **따라쓰기**는 trim 후 **대소문자 구분 완전 일치**이며 일치하는 즉시 완료. 문장은 알람이 고른 것 중 무작위, **앱 언어의 문장**으로 출제·판정합니다.
- 미션 완료 시 **지금 울리는 알람만** 멈추고 반복 예약은 유지합니다. 알람을 찾을 수 없거나 문구 파일이 없어도 **미션 없이 꺼지지 않습니다**(기본 미디어·소리 + 흔들기로 대체).
- 리스트: 시각, 요일, 타이틀, on/off, "다음 울림까지 N시간 M분"(분 단위 올림, 해당 없으면 숨김). 삭제는 리스트 왼쪽으로 밀기, 카드 길게 누르기, 편집 화면 휴지통(확인창).
- 실행 화면: **전체 화면 배경 동영상**(음소거·반복) 위에 날짜·큰 시각(24시간제 `HH:mm`)·타이틀·미션 시작. 날짜·시각은 상단 1/3, 미션 시작은 하단. 뒤로가기로 끄는 경로가 없고, 울리는 동안 화면이 꺼지지 않습니다. 미션 완료 시 "미션 완료! 좋은 아침이에요"와 진동 후 닫힙니다.
- 미리보기는 **편집 화면에서만** 열 수 있고 `미리보기 종료` 버튼이 있습니다. 미션을 해 볼 수 있지만 알람을 멈추지 않습니다.
- 화면: 메인 / 편집·생성 / 미션 문장 고르기 / 설정(언어, 권한 안내) / 언어 선택 / 알람 실행 / 미션 / 미리보기.
- **비범위:** 다크 테마, 통계, 결제, 클라우드, 태블릿. 스누즈는 미루기(11.6), 단발 알람은 퀵알람(11.7)으로 한정해 허용합니다. 7일을 넘는 날짜 지정·요일별 다른 시각·순환 일정·달력 직접 지정은 이번 범위 밖입니다(기획서 3절·11.1).

## 플랫폼 대응표 (iOS → Android)

아래는 **출발점 제안**입니다. 실제 API 제약은 구현 전에 공식 문서로 확인하세요(Android는 버전마다 알람·전체 화면 알림 정책이 자주 바뀝니다).

| iOS | Android 후보 | 메모 |
|---|---|---|
| AlarmKit(시스템 알람) | `AlarmManager.setAlarmClock()` + `BroadcastReceiver` | Doze에서도 정확히 울리도록 알람 시계 API 사용. 알람 앱용 정확한 알람 권한(`USE_EXACT_ALARM` 등) 정책을 확인 |
| 시스템 울림 → 앱 열기 | 수신 → **포그라운드 서비스**로 소리 재생 + 전체 화면 인텐트 알림 → 실행 Activity | 잠금화면 위로 띄우려면 `showWhenLocked`/`turnScreenOn`과 `USE_FULL_SCREEN_INTENT`(Android 14+ 정책) 확인 |
| 앱이 소리를 직접 재생(시스템 소리가 멈춘 경우) | Android는 **앱이 항상 직접 재생** | 알람용 오디오 속성(`USAGE_ALARM`)으로 무음 모드에서도 울리게. `.caf`는 필요 없음 |
| SwiftData | **Room**(SQLite) | 저장이 원본, 예약은 파생. 저장 후 예약, 실패해도 데이터는 유지, 앱 시작 때 다시 맞추기(reconcile) |
| `AlarmService`(변경의 단일 진입점) | Repository/UseCase 한 곳 | 화면에서 DAO를 직접 수정하지 않습니다 |
| 재부팅 후 예약 유지(OS가 처리) | `RECEIVE_BOOT_COMPLETED` 수신 후 **재예약 필수** | Android는 재부팅하면 알람이 사라집니다 |
| Core Motion `userAcceleration` 1.5g | `SensorManager` `TYPE_LINEAR_ACCELERATION` (m/s², 1g ≈ 9.8. iOS 1.5g는 쉬워 Android는 4.0g ≈ 39.2로 확정) | 0.35초 안의 피크 무시, 시작 0.5초 무시(iOS `ShakeCounter` 규칙). **임계값은 실기기에서 조정**(`ShakeCounter.DEFAULT_THRESHOLD` 한 곳) |
| `LoopingVideoView`(음소거 반복 영상) | Media3 ExoPlayer(`repeatMode = ALL`, 볼륨 0) 또는 `VideoView` | 영상이 알람 소리(오디오 포커스)를 끊지 않게 |
| 앱 언어 설정 | `AppCompatDelegate.setApplicationLocales` / 앱별 언어 + `values`/`values-en` `strings.xml` | 문구 원본은 `../shared-resources/Copy/ui_strings_{ko,en}.json`. Android에서는 `strings.xml`로 옮깁니다 |
| 알람 권한 창 | 알림(`POST_NOTIFICATIONS`, Android 13+), 정확한 알람, 전체 화면 알림 | 권한 요청은 사용자 동작(저장·켜기·`설정 열기`)에서만 합니다 |
| `OpenSettingsButton` | `Settings.ACTION_APP_NOTIFICATION_SETTINGS` 등 앱 설정 화면 인텐트 | iOS와 달리 알람 관련 설정 화면으로 더 직접 보낼 수 있음 |

## 리소스 규칙

- `../shared-resources/assets_catalog.json`이 미디어·소리·미션 목록의 기준입니다. 코드에 하드코딩하지 말고 카탈로그를 읽어 쓰세요. `file` 경로(`Media/...`, `Sounds/...`)는 `assets/` 아래 같은 구조에 두고 `AssetManager`로 엽니다(iOS와 달리 평탄화하지 않으므로 경로 그대로 사용 가능).
- 카탈로그의 `alarmFile`(`.caf`)은 iOS 전용이라 Android에서는 무시합니다. 소리는 mp3만 씁니다. `아침이 왔다잖아`(33.7초)는 iOS 알림 소리의 30초 제한 때문에 iOS에서 실기기 확인 대상이지만, Android는 앱이 직접 반복 재생하므로 같은 제한이 없을 것으로 봅니다(구현 후 확인).
- **소리·미디어 표시명은 앱 언어를 따라갑니다.** 카탈로그 id(`media_...`, `sound_...`)를 키로 한/영 문구에서 찾고, 없으면 카탈로그 `displayName`(한국어)으로 대체합니다. 영어 이름: `Morning Has Come`, `Yar Song`, `Puppy Smash`, `Cat vs. Phone`, `Shaky Alarm`.
- 따라쓰기 문장은 `Copy/transcription_prompts.json`(`categories` 한/영 표시명 + `prompts[].category` + `prompts[].text`의 같은 id에 `ko`/`en` 문장)입니다. 문장을 추가할 땐 두 언어를 함께 넣고, 띄어쓰기가 헷갈리지 않는 짧은 문장으로 씁니다. 영어는 첫 글자만 대문자, 중간 대문자·아포스트로피 금지(키보드가 ’로 바꿔 불일치할 수 있음).
- 미디어 영상은 이미 렌더링되어 있습니다(1080×1920, 7초, 무음 반복). 생성 스크립트는 macOS 전용 Swift라 이 프로젝트에는 없습니다. 새 영상이 필요하면 iOS 저장소의 `AlarmApp-iOS/Tools/`를 참고하세요. 영상에는 날짜·시각(상단 1/3)과 미션 버튼(하단)을 가리는 연출을 넣지 않고, **화면 전체 번쩍임은 금지**(광과민성)입니다.

## 열린 결정 (사용자와 먼저 정할 것)

- (확정) `minSdk 28`/`targetSdk 36`, 단일 모듈 `app`, Hilt + Navigation Compose, `USE_EXACT_ALARM`.
- Play 스토어 배포 시 알람 앱의 정확한 알람·전체 화면 알림 권한 선언 정책 확인(열림).
- 11절 구현 시 정할 것: 일회성 예약(퀵알람·미루기·이번만 변경)의 개수 한도·Doze/재부팅 지속성, 같은 시각에 여러 알람이 겹칠 때 실행 화면·소리 정책, 미루기 재울림이 같은 알람의 다음 정규 회차와 겹치거나 지나는 경우, 시간대·일광 절약 시간 처리(기획서 11.10). 자동 처리 방식을 추정해 구현하지 말고 사용자와 정합니다.

## 확인 목록 (실기기에서 확인할 것)

① 알림 권한 창과 정확한 알람 허용 흐름 ② 지정 시각에 소리와 함께 정확히 울림(Doze, 절전 모드) ③ 잠금 상태에서 화면이 켜지고 실행 화면이 뜨는지 ④ 앱이 꺼진/백그라운드/포그라운드 상태 각각에서 울릴 때 ⑤ 알림에서 앱 열기, 알림 스와이프로 알람이 꺼지지 않는지 ⑥ 무음·방해 금지 모드에서 소리 ⑦ 흔들기 임계값(너무 쉽거나 어려운지) ⑧ 미션 완료 시 소리 정지와 다음 요일 예약 유지 ⑨ **재부팅 후 알람 재예약** ⑩ 앱 강제 종료 후에도 울리는지 ⑪ 영어 따라쓰기에서 키보드 자동 대문자, 한글 조합 중 판정이 자연스러운지 ⑫ 제조사별 배터리 최적화(삼성·샤오미 등)에서 알람이 죽지 않는지

11절 확장 구현 후 추가 확인: ⑬ 퀵알람: 고른 분 뒤에 울리는지, 무음·방해 금지에서 소리·진동, 중지로 미션 없이 꺼지는지, 앱 종료·재부팅 후에도 울리는지, 실행 화면이 뜨지 않는지, 종료·취소 후 목록에서 사라지는지, 5개 초과 안내 ⑭ 알람 미루기: 버튼 후 소리 정지와 간격 뒤 재울림, 앱 종료·재부팅 후 재울림, 횟수 도달 시 버튼 숨김, 미션 완료 후 대기 재울림 없음, 끄기·삭제·건너뛰기 때 예약 취소 ⑮ 이번만 변경: 변경일에 새 시각으로 울리고 원래 시각엔 안 울리는지, 건너뛴 날 안 울리는지, 다음 주 같은 요일은 기본 시각, 재부팅·장기간 앱 미실행 후 동작, 일회성 예약 개수 한도 ⑯ 메모 읽어주기: 읽는 동안 알람 소리가 작아져 음성이 또렷이 들리는지, 끝나면 소리 복구, 한/영 음성, 미루기 재울림에서 다시 읽지 않는지, 가끔 안 읽히는 현상이 없는지(여러 번 반복)

## 리스크

- Android는 제조사·버전별로 알람, 백그라운드 서비스, 전체 화면 알림 정책이 다릅니다. 실기기(가능하면 2종 이상)로 확인해야 합니다.
- 사용자가 알림을 스와이프하거나 앱을 강제 종료하면 미션 강제가 약해집니다. 포그라운드 서비스 + 지속 알림으로 줄이되 100% 차단은 어렵다고 보고, 한계는 리스크로 수용합니다.
- 흔들기 기준값과 따라쓰기의 완전 일치 규칙(띄어쓰기 실수로 실패 가능)은 실기기에서 보정합니다.
